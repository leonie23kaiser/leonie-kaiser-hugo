# Content Workflow

All commands run from the **repo root** (not from `src/growthtogether.at/`). The `--source` flag tells Hugo where the project lives.

```bash
hugo server --source src/growthtogether.at -D     # → http://localhost:1313
hugo --source src/growthtogether.at --minify      # → src/growthtogether.at/public/
```

**There is no `data/site.yaml`.** Most of what this doc used to describe as "edit the YAML" is now "edit the template/data file directly" — see the sections below.

## Edit homepage copy (hero, pain points, Leistungen teaser, etc.)

The homepage is hardcoded HTML in `layouts/_default/home.html` — there's no separate content file to edit. Open the file, find the relevant `<section id="...">`, edit the copy in place. Brand voice rules in `AGENTS.md` (repo root) are canonical — check them before writing new copy, especially the Wort-Blacklist/Whitelist.

Sections currently on the homepage: hero, "Kennen Sie das?" (pain points), "Was ich für Sie tue" (Leistungen teaser, 3 cards), Datenschutz/Compliance-first, Über mich, Prozess (3 steps), Testimonials, "KI-Potenzialanalyse"-Promo, Kontaktformular.

## Edit a Leistungsbereich page (Termine & Anfragen, Dokumentation & Wissen, Nachsorge & Kundenbindung, Sichtbarkeit & Inhalte)

Open `data/branchen.yaml`, find the entry by `slug`, edit `schmerz`/`intro`/`usecases`/`beispiel`/`faq`. The matching `content/leistung-*/_index.md` file only holds SEO front matter (title/description/url) — the actual copy lives in `branchen.yaml`. See [content-model.md](content-model.md) for the full field schema.

Conventions from the file's own header comment: Sie-Form, gendered neutrally, `beispiel` scenarios are illustrative only (never a real client), full sentences (no bullet fragments) in `beispiel`, sparse `Gedankenstriche`.

## Add a new Leistungsbereich

1. Add an entry to `data/branchen.yaml` with a new `slug`.
2. Create `content/leistung-<name>/_index.md` with `type: branche` and matching `branche_slug`/`url`.
3. Link it from `layouts/leistungen/single.html` and cross-links in `layouts/branche/single.html`.
4. Consider whether `strategie/service-katalog.md` and `tools/pdf-templates/service-katalog/service-katalog.html` (the downloadable PDF) should list it too — both are edited and regenerated by hand, not templated from `branchen.yaml`.

## Write a blog post

**Use the `blog-post` skill** (`.claude/skills/blog-post/`) — it's the guided, multi-step flow: Redaktionsplan → Keyword-Check → Headline → Outline-Freigabe → Text → Bildvorgaben → Hugo-Build-Check, with Leonie's sign-off at each step. It reads `AGENTS.md`, `strategie/blog-konventionen.md`, and `strategie/blog-post-prompt.md` as its source of truth — don't duplicate those rules here.

Manually, a post is `content/journal/<slug>.md` — see [content-model.md](content-model.md) for the front-matter schema (`cover`, `coverAlt`, `coverCredit`, `category`, `readingTime`, `tags`, `draft`, etc.).

**Publishing is scheduled, not immediate.** Posts can be future-dated (`date:`); the deploy workflow runs `--buildFuture` on a Tuesday cron, so a future-dated post goes live automatically at its `date`, then triggers a GitHub issue (HITL notify) for Leonie to review. See [deploy.md](deploy.md). Set `draft: true` while a post isn't ready yet — draft posts never publish regardless of date.

## Replace a photo (the right way — pipeline)

For anything new (portraits, blog covers, banners):

1. Drop the new source image into `src/growthtogether.at/assets/images/<sensible-subfolder>/` (high-res, e.g. 1600px wide).
2. Call it via `partial "picture.html"` — see [assets-styles.md](assets-styles.md) for the parameter list.
3. Hugo regenerates WebP + original-format variants on next build.

Blog covers (`assets/images/blog/`) already follow this pattern — copy that as your template.

## Replace a photo (current pragmatic way — pre-renders)

Most of `home.html` (and some other layouts) still use pre-rendered `static/images/<name>.{png,webp}` pairs referenced via inline `<picture>` blocks. To swap one:

1. Pre-render a PNG and WebP at the same dimensions.
2. Save both as `static/images/<name>.png` and `static/images/<name>.webp` (overwrite, or new name + update the file path in the layout's inline `<picture>` block).

Keep the source in `assets/images/reserve/` for future re-rendering. Don't add *more* pre-rendered pairs for new content — use the pipeline path above instead.

**Image dimension cheat-sheet (current site, subject to change as sections get redesigned):**

| Slot | Dimensions | Aspect | Notes |
|---|---|---|---|
| Hero portrait (Bild-1) | ~1200×1500 source | varies by crop | LCP image, preloaded + `fetchpriority="high"` |
| About portrait (Bild-2) | 4:5 crop | 4/5 | Card layout in "Über mich" |
| Conscious Consultant badge | square | 1/1 | Overlaid on about portrait |
| OG default | 1200×630 | 1.91/1 | Static, branded, fallback for all pages without a specific `image`/`ogImage` |
| Blog cover | 16:9 | 16/9 | Rendered via `picture.html`, see `content-model.md` |

Verify actual current dimensions against the file before assuming — this table drifts easily.

## Update Calendly URL

`config/_default/params.toml` has a `calendly` key, but **no live template currently reads it** — every "Termin buchen" CTA across the site (nav, homepage, Leistungsseite, journal posts, all `type/single.html` layouts) hardcodes the literal `https://calendly.com/leonie-kaiser/ki-potentialanalyse` URL. Changing `params.toml`'s `calendly` value alone does nothing. To actually change the booking link, find-and-replace the literal URL across `layouts/` (nine occurrences as of this writing — grep for `calendly.com/leonie-kaiser` to find them all), and update `params.toml` to match so the two don't drift.

## Add a nav / footer link

**`menus.toml` doesn't do anything** — the real nav and footer are hardcoded in `layouts/partials/nav.html` and `layouts/partials/footer.html`. Edit those files directly, in both the desktop link list and the mobile menu block in `nav.html`. See [config.md](config.md).

## Edit Impressum / Datenschutz / FAQ / EU AI Act / DSGVO pages

Standard Markdown front matter + body for the first two (`content/impressum.md`, `content/datenschutz.md`), rendered by `layouts/impressum/single.html` / `layouts/datenschutz/single.html`.

FAQ, EU AI Act, and DSGVO pages mix front matter (`faqs:` list) with a layout that either duplicates the visible copy (`faq.md` — **dual-source, must edit both `content/faq.md` and `layouts/faq/single.html` in lockstep**) or loops `.Params.faqs` directly (`eu-ai-act`, `dsgvo` — single source, front matter is enough). See [content-model.md](content-model.md).

## Update brand colours

**Two places must change in lockstep:**

1. `config/_default/params.toml` — the `brand*` keys
2. `src/growthtogether.at/assets/css/brand.css` — the `:root { --lk-* }` block at the top

If you only update one, the JSON-LD / OG / theme-color meta tags will drift from the visual design.

## Draft / preview before publish

- `hugo server --source src/growthtogether.at -D` shows drafts (`draft: true` in frontmatter) and honours future dates.
- Open `http://localhost:1313/` in the browser. Live reload is on.
- For future-dated content specifically, add `--buildFuture` to preview what the Tuesday cron deploy will actually publish.

## Publish (deploy)

See [deploy.md](deploy.md). **Do not push to `main` / deploy without explicit go-ahead** — live site is a paying client.

## Quick reference — "who edits what"

| Task | File(s) |
|---|---|
| Homepage copy | `layouts/_default/home.html` (hardcoded, no data file) |
| Leistungsbereich copy | `data/branchen.yaml` |
| Blog post | `content/journal/<slug>.md` — use the `blog-post` skill |
| Phone, email, Calendly, LinkedIn | `params.toml` (check individual CTAs aren't hardcoded) |
| Brand colour | `params.toml` + `brand.css` |
| Nav / footer links | `layouts/partials/nav.html` + `footer.html` directly — **not** `menus.toml` |
| Impressum / Datenschutz | `content/impressum.md` / `datenschutz.md` |
| FAQ | `content/faq.md` **and** `layouts/faq/single.html` (dual-source, keep in sync) |
| EU AI Act / DSGVO copy | `content/eu-ai-act/_index.md` / `content/dsgvo/_index.md` front matter (single-source) |
| New image (proper way) | `assets/images/<subfolder>/...` + `picture.html` call |
| New image (quick way, discouraged for new content) | `static/images/...{png,webp}` + inline `<picture>` |
| Service-Katalog PDF | `tools/pdf-templates/service-katalog/service-katalog.html`, regenerate manually |
| `llms.txt` (AI/GEO summary) | `static/llms.txt`, hand-maintained, update when services/pricing change |
| Layout / new page type | new `content/<type>/` + `layouts/<type>/single.html` + `partials/schema.html` if it needs structured data |
